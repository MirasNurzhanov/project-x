# H10 — Blocking backend and frontend CI

Status: blocking workflows implemented and their commands exercised locally. The final full backend run is red because of unrelated changes added to the shared worktree during this batch. GitHub Actions execution and repository branch-protection settings were not changed remotely.

## Gates

Backend `.github/workflows/backend-ci.yml` runs on every pull request, push and manual dispatch. Its `Backend checks` job uses Ubuntu 24.04, Python 3.12, PostgreSQL 16 and Redis 7 with service health checks. It installs the existing requirements, runs `pip check`, runs Django's deploy check with warnings treated as failures, checks migration drift, runs the full SQLite backend suite, then runs PostgreSQL/Redis publishing, impression, Hi, socket and query-budget regressions.

`core.ci_test_settings` inherits safe test media/push settings but requires explicit CI PostgreSQL/Redis URLs. It refuses a SQLite fallback, so concurrent-writer tests cannot silently skip in that job. Django creates and removes `test_aura_ci`; the workflow uses only disposable service credentials. Deployment checks exercise `core.settings` with DEBUG off, explicit host/proxy configuration and secure-cookie/HSTS settings. Test-specific settings are not used to pass the deploy gate.

Mobile `.github/workflows/frontend-ci.yml` runs on the same events. Its `Frontend checks` job uses Ubuntu 24.04 and Node 24, runs `npm ci`, then lint, `npm run typecheck` and Jest with `--ci --runInBand`. The existing advisory React Doctor workflow is preserved. Node 24 exceeds Expo SDK 54's documented minimum and matches the local test runtime; Python 3.12 matches the backend Dockerfile.

Neither workflow uses continue-on-error, conditional failure suppression or swallowed exit statuses. YAML structure, triggers and failure behavior were reviewed. A failed command fails its job. These jobs can be selected as required checks in repository branch rules; local workflow files cannot themselves impose remote merge protection.
