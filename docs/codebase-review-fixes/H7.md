# H7 — Deployment-only migrations

Status: implemented in the repository; Railway configuration is not verified or changed.

The Procfile web command checks ASGI capacity configuration, then starts uvicorn.
It performs no schema or data repair. Migrations and interest seeding
remain in the release command. `fix_age_tiers` is no longer a startup operation.
Migration `users.0038_recalculate_age_tiers` uses historical models and two SQL
updates, repairs the eighteenth-birthday boundary, and leaves missing DOBs alone.
It is idempotent for the execution date; reverse is intentionally a no-op rather
than restoring incorrect classifications. The manual repair command remains
available, without printing usernames or individual ages.

## Deployment sequence

1. Take the normal database backup and provision the required variables/storage
   described in M3, M6, M11, M12 and M15. Do not deploy against an absent private bucket.
2. On Railway, explicitly configure the **web service's pre-deploy command** as
   `python manage.py migrate --noinput && python manage.py seed_interests`.
   Do not assume a Procfile `release:` entry configures Railway automatically.
   Railway runs pre-deploy before the deployment starts and a failing command
   prevents deployment. See [Railway pre-deploy commands](https://docs.railway.com/deployments/pre-deploy-command).
3. Keep the web start command equal to the Procfile web entry. Run the moderation
   worker as its own supervised service, after schema changes complete. Do not
   attach migration hooks independently to every worker or replica.
4. Verify migration 0038 is applied; then restart/scale a web process and verify
   its logs show application startup, not migration or age-repair execution.

The one-off migration replaces repair-on-boot; it is not a new daily birthday
scheduler. No production migration, scaling action or deployment was performed.

Tests: `core.test_operations` checks application-only startup, migration-safe
models, boundary behavior, missing DOBs and idempotence. These passed on SQLite
and disposable PostgreSQL. Migration drift and production-shaped deploy checks
also passed. See [OPERATIONS_VALIDATION.md](OPERATIONS_VALIDATION.md).
