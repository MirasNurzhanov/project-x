# H9 — Feed impression writes and query budget

Status: fixed; the original query-budget regression passes without changing its limits.

## Measured behavior

`CaptureQueriesContext` instrumented the actual requests in `core.test_query_budgets.QueryBudgetTests.test_ranked_feed_costs_one_ranking_pass_not_one_per_swipe`. The fixture warms chronological serialization, clears impressions, then requests a ranked page of three and its continuation.

| Request | Before | After | Unchanged budget |
| --- | ---: | ---: | ---: |
| First ranked page | 37 | 36 | 50 |
| Continued page | 9 (failed) | 8 (passed) | 8 |

Counts include Django transaction/savepoint statements and were measured on SQLite. The same budget test also passes against PostgreSQL 16 with Redis 7. Captured SQL is included with the deliverable logs.

## Cause and fix

`recs.exposure.mark_served` ran a bulk upsert for timestamps/source, followed by a separate UPDATE for counts. The latter was redundant for newly served pages and used `first_served_at < now` to distinguish new rows, which also missed repeated serves at an identical timestamp.

One parameterized PostgreSQL/SQLite `INSERT ... ON CONFLICT DO UPDATE` now inserts new rows at count 1 and increments existing counts in the same statement. It preserves the original first-served timestamp and updates the latest timestamp/source. Django's bulk-create `update_fields` cannot express that increment, which is why the small SQL operation is explicit. Values remain bound parameters; only the model's quoted table name and generated placeholders enter SQL text.

Duplicate IDs within one page count once. Batches respect the backend parameter limit and stay in one transaction. Ranking, eligibility rules, serializers and query-budget thresholds are unchanged.

## Verification

New exposure regressions check new, repeated and mixed batches; repeated calls at exactly the same time; preserved timestamps/source; deduplication; and one write for a 50-item page. Four concurrent PostgreSQL writers produce a single impression with count 4. All 37 PostgreSQL/Redis regression tests pass, including the existing feed budget. Full backend results are in H10.md.

Changed: `recs/exposure.py`, `recs/tests/test_exposure.py`. No model or budget changes.
