# L5 — map.tsx is excessively large

## Status
FIXED

`app/(tabs)/map.tsx` went from 4,385 lines to 432:
- **What stays:** the screen itself (`MapScreen`, its state, effects and wiring) is unchanged.
- **What moved:** every other top-level declaration moved into eight files under `components/map/`.
  Each moved word for word, with its comments.
- **What changed besides the move:**
  - `export` on the names another file now needs;
  - per-file import lists;
  - a short header per file;
  - five section comments relocated to the files they describe;
  - two unused imports removed.

No logic, state management, props or component names changed.

Typecheck, lint and the full test suite pass apart from one pre-existing failure. No test renders
`MapScreen` itself, and the screen was not run on a device.

## Severity
Low

## Original problem
Review, page 36:
- `app/(tabs)/map.tsx` was 4,384 lines, with 15 `useState`, 6 `useEffect`, 4 `useRef` and about 20
  components defined inline.
- Data fetching and location had already moved into `useMapData` and `useMapLocation`.
- What remained were presentational components that do not depend on the screen's state, such as
  `DotMarker`, `AvatarMarker`, `SelfMarker`, `ClusterMarker`, `StoryMarker`, `MusicZoneBadge`,
  `TopBar` and `CreateStoryModal`.
- **Suggested fix:** move them to `components/map/` as-is.

## Root cause
Components and styles accumulated in the screen file as it grew. The hooks had been extracted, but
the rendering code had not.

## Investigation
- **Inventory** (`scratchpad/l5_inventory.js`): the TypeScript compiler API listed every top-level
  statement in `map.tsx`, with its line range including comments, and which other top-level names
  it references.
- **What `MapScreen` depends on:** `makeStyles`, `LOCATE_SIZE`, `LOCATE_INSET`, and eight
  components: `MapPermissionGate`, `MapCanvas`, `TopBar`, `MapNotices`, `MapSheets`,
  `CreateStoryModal`, `MapToasts` and `LocateButton`.
- **Why the rest is safe to move:** every other declaration is a module-level function, constant,
  interface or type. None of them can capture `MapScreen`'s local state; anything they use arrives
  as props or is imported.
- **One piece of module-level mutable state:** `loadedAvatars`, the set of decoded avatar URLs. It
  moved into the same file as its only users (`AvatarMarker`, `SelfMarker`), so there is still
  exactly one instance.
- **No import cycles:** the references allow a strict ordering of files:
  1. constants;
  2. styles and helpers;
  3. markers;
  4. layers;
  5. the screen, alongside sheets, chrome and the composer.
- **Tests that could be affected:**
  - No test imports anything from `map.tsx`.
  - `services/__tests__/noAutomaticVisibility.test.ts` scans all of `app`, `components`,
    `services`, `context` and `hooks` for location-visibility writes, and names
    `app/(tabs)/map.tsx` among its entry points. The moved code stays inside the scanned
    directories.
  - `mapGhostPrivacy.test.tsx` tests `useMapData` and `useMapSheets`, which were not moved.

### How the code was moved
The split was scripted (`scratchpad/l5_split.js`) rather than retyped.

**What the script does:**
- Moves each top-level declaration's exact source text, with its leading comments and any comment
  on the same line after it.
- Keeps declarations that were adjacent in the original with their original spacing.
- Adds `export` only to the names used across files: 17 plus `MapScreen`'s existing default
  export.
- Copies the original import statements into each file and removes the names that file does not
  use. A comment on an import whose name was removed is dropped with it: the `PermissionState`
  note in `map.tsx` now lives only in `MapChrome.tsx`, which still imports it.
- Adds a short header to each new file.
- Puts a "where the pieces live" note at the top of `map.tsx`, replacing a stale "everything still
  local is a prop bag for a component in this file" comment.
- Relocates section comments to the code they describe:

  | Comment | Now in |
  |---|---|
  | `PARKED_MARKERS` explanation | `MapMarkers.tsx` |
  | Ring-colour note | `MapLayers.tsx` |
  | "Map layers" | `MapLayers.tsx`, before `ZoneLayer` |
  | `SHEET_H`/`SPRING_CFG` note | `MapSheets.tsx`, which imports those |
  | Removed zone banner note | `MapChrome.tsx`, after `TopBar` |
  | "Two things this screen deliberately no longer does" | `map.tsx`, above `MapScreen` |

**What it checks before writing:**
- Every declaration appears exactly once, verbatim, in its target file.
- Each relocated comment is in exactly its intended file.
- There are no import cycles.

**Afterwards:** the only manual edit was removing an unused `radius` import from `MapLayers.tsx` and
`MapMarkers.tsx`. Local props named `radius` had made them look used to the script.

**A first run was discarded.** It normalised blank lines and detached one same-line comment. The
script was corrected and re-run from HEAD's `map.tsx` plus the one L2 edit to it
(`scratchpad/l5_restore_input.js`).

### What was deliberately not done
- **`MapScreen` untouched:** its hooks and `useState`/`useEffect` count are unchanged.
- **No architecture changes:** no state-management restructuring, and no changes to the existing
  hooks.
- **No renaming:** no component was renamed or re-propped.
- **No further splitting:** `mapStyles.ts` (1,067 lines) and `MapMarkers.tsx` (945) were not split
  into per-component styles or files. This is a decomposition along the seams the file already
  had.

## Why this fixes it
- **Screen file reduced:** `map.tsx` now contains only the screen, at 432 lines.
- **Components grouped:** the presentational components live in `components/map/`, grouped by what
  they draw, and each can be read and changed without scrolling past four thousand lines.
- **Same code, same behaviour:** every moved declaration is the same text as before, so the render
  tree, React keys, props and hook order are the same.

## Tests added or changed
None were added for L5; this is a code move with no behaviour change. What guards it:
- `npx tsc --noEmit`, which catches any missing import or export;
- lint;
- the full Jest suite, including `noAutomaticVisibility.test.ts` over the new files;
- the script's own consistency checks.

  graph, and `written`.

**Diff:** `git diff --stat` → `app/(tabs)/map.tsx` shows the removal, and `components/map/` is new

## Compatibility / deployment notes
- **Behaviour:** no runtime change is intended; the component code is identical.
- **Imports:** Metro resolves the new `@/components/map/*` modules. Only the router uses
  `map.tsx`'s default export.
- **Git history:** history for the moved code now starts at the new files. `git log --follow` on a
  new file will not show its time inside `map.tsx`, but `git log -S "<code>"` still finds it.

## Remaining risk
- **No screen-level test:** no test renders `MapScreen` or its canvas, sheets or chrome, so
  behaviour is verified by typecheck, lint and the existing hook tests, not by rendering the
  screen.
- **Not run in an app:** the screen was not run on a device or simulator.
- **React Compiler not measured:** the compiler works per component and the components are
  unchanged, but compiled output was not compared.
- **Large files remain:** `mapStyles.ts` and `MapMarkers.tsx` are still large, and `MapScreen`
  still holds the same amount of state.
