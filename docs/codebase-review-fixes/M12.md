# M12 — Environment configuration matches the application

Status: example configuration updated; real deployment variables were not
printed, changed or validated against external services.

Removed obsolete Cloudinary variables. The example now documents all six R2
names: R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY, R2_BUCKET_NAME,
R2_PRIVATE_BUCKET_NAME, R2_ENDPOINT_URL and R2_PUBLIC_URL. It distinguishes the
S3 endpoint from the public media origin and requires a separate non-public bucket
for new chat/Swift media. Deploy checks reject a missing/shared private bucket or
an unsigned/public-domain private-storage configuration; they do not inspect R2.

Required `config()` calls without defaults were inventoried: SECRET_KEY, the five
original R2 values, and DB_NAME/DB_USER/DB_PASSWORD/DB_HOST/DB_PORT only if DATABASE_URL
is absent. R2_PRIVATE_BUCKET_NAME has a compatibility default but is operationally
required for this rollout. Hosts/proxy trust and shared Redis are also production
requirements even where settings parsing supplies defaults.

MODERATION_WORKER_TOKEN is documented as the shared Go/Django credential; blank
closes the internal moderation endpoints. The example also covers supervised
moderation execution, synchronous-mode restrictions and the optional Go push
URL/shared-token/dead-token callback settings. All values are placeholders.

Checks: migration drift passes; `check --deploy --fail-level WARNING` passes with
DEBUG=False and explicit dummy hosts, credentials, proxy and separate bucket
values. No provider connections or production mutations occurred. The actual
Railway proxy path, storage permissions and worker processes require external
verification. See [OPERATIONS_VALIDATION.md](OPERATIONS_VALIDATION.md).
