# M3 — Upload validation and serving

Status: implemented for new DM/club images and Swift video/posters. External
private-bucket provisioning, native playback and legacy public-media remediation
remain unverified. No deployment performed.

Images: still JPEG/PNG/WebP, actual bytes <=10 MiB, <=16 megapixels and <=8192
pixels per side. Pillow verifies and fully decodes actual content; caller MIME
and extensions are not trusted. A fresh raster is encoded with server-controlled
MIME/UUID filename, stripping EXIF, comments and appended HTML/polyglot content.
Animated formats, SVG, HTML, truncated or oversized input are refused. EXIF
orientation is applied before metadata removal; alpha transparency is preserved.

Videos: MP4/QuickTime, actual bytes <=200 MiB, bounded ISO-BMFF parsing requiring
recognized ftyp, media data and a video-track handler. Filenames/MIME are canonical.
This validates the container, NOT every codec/sample or the claimed duration.
Cloudflare moderation remains separate and fail-closed. A decoder sandbox or
transcoding pipeline is not newly claimed; playback must still be device-tested.

New files use a distinct `R2_PRIVATE_BUCKET_NAME`, no public custom domain,
signed URLs valid 300 seconds, private/no-store caching, and attachment disposition.
The bucket MUST have public r2.dev access and public domains disabled externally.
The deploy check rejects missing/shared buckets and public URL configuration.
Storage migrations only change field storage; no existing rows or objects are
removed or moved. Existing unprefixed R2 files and legacy image_url values retain
read compatibility and remain as public as before: inventory and migrate those
objects separately before claiming historical media is private.

Authorized API serializers issue the signed URLs using existing relationship,
membership and Swift visibility checks. Possession of a signed URL authorizes
fetch until expiry; revocation is not instantaneous. Cloudflare moderation workers
obtain fresh source URLs for each attempt. Verify the transformation source
allowlist supports signed private R2 URLs and that external edge logs/caches do
not retain or expose signed URLs or extracted private frames.

Tests: `core.test_uploads` covers actual formats, content rewriting, metadata,
dimensions/bytes, invalid video containers, serializer fields and signed URLs.
`core.test_message_media` proves REST rejects disguised active content while valid
uploads/legacy reads work. Swift fixtures now use valid images and structural
video fixtures. Related Swift/message suites have only the already-reproduced
Swift blocked-query-count baseline failure; no new upload/moderation failures.

Rollout: provision private R2 bucket/permissions, set R2_PRIVATE_BUCKET_NAME,
run deploy checks and the three generated storage-field migrations, verify native
DM/club image and MP4/MOV playback including signed URL expiry, and verify AI
moderation access. Never silently fall back to the public bucket on failure.
