# M5 — Removing a connection erased both message histories

Status: fixed in code; regression tests pass on SQLite and PostgreSQL 18.6.

`RemoveFriendView` previously hard-deleted every Message between the two users.
It now removes the relationship and updates only the initiating participant's
existing `deleted_for_sender` / `deleted_for_receiver` flags in one transaction.
The peer's flags, message rows, images, report snapshots and unrelated threads
remain intact. Reconnecting does not restore messages the initiator hid.

The surviving copy is accessible through the paginated history endpoint even
after the relationship ends. The friends-list response adds `archived`, separate
from `friends` and `connections`, so archives confer no friendship, location or
profile privileges. Blocks still hide both directions. Archived read receipts
must name a real visible incoming message in that conversation.

The mobile Chats list shows archived conversations and their history. The
history response's `can_send` controls the composer and retry path. Archived
contacts are excluded from friendship counts and map connection IDs.

REST and socket sends recheck the relationship after moderation, inside a
transaction that locks participants in PK order. Removal takes the same locks:
a send is either saved before removal and hidden appropriately, or refused
after removal. External moderation does not run while holding those locks.
