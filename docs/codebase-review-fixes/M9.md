# M9 — Expo ticket handling and dead-token cleanup

Status: immediate ticket handling implemented and tested; live delivery and Go
callback configuration remain unverified. Delayed receipt polling is not implemented.

Django inspects HTTP status and positional Expo tickets, validates ticket count
before matching recipients, and handles single-ticket object responses. A
`DeviceNotRegistered` ticket clears the exact token on Device and the legacy
User fallback in one transaction. It never deletes the Device identity, name,
platform or installation ID. A delayed result for an old token cannot clear a
newly rotated token. Malformed tickets and other provider errors do not invalidate
credentials and are logged without token/body/provider-message contents.

The Go dispatcher now wires its dead-token callback to the authenticated Django
endpoint `/api/internal/push/dead-tokens/`. Configure `PUSH_DEAD_TOKEN_URL` on Go;
its `PUSH_AUTH_TOKEN` must match Django's `PUSH_DISPATCHER_TOKEN`. The endpoint
rejects an absent secret, ordinary user authentication and invalid/oversized
token lists. The callback runs inside the existing bounded worker, has a two-second
HTTP timeout and at most three attempts, and does not follow redirects. Failed or
unconfigured cleanup is observable. A failed callback is not durably queued; a
later push can trigger another attempt.

Django's fallback sender has two worker threads and at most 32 admitted tasks.
Overflow or transport/cleanup failures do not roll back already-saved messages.
Push delivery remains best-effort, not a durable notification-delivery guarantee.

Expo distinguishes initial tickets from later delivery receipts; errors can first
appear in a receipt. This patch fulfills ticket inspection, but cannot claim that
every dead token or delivery failure is detected without receipt polling.
See [Expo ticket and receipt documentation](https://docs.expo.dev/push-notifications/sending-notifications/).

Tests: `notifications.test_push_delivery`, existing push targeting/transport tests,
and `services/go-push/dead_tokens_test.go`. They cover identity preservation,
rotation, malformed responses, other errors, nonfatal failures, callback auth,
retry bounds, redirect rejection, chunking and payload-free logs. Go race tests
and PostgreSQL regressions pass. See [OPERATIONS_VALIDATION.md](OPERATIONS_VALIDATION.md).
